# Restate Operator v2.7.1 Release Notes

## Highlights

- **Fix: the Pod Identity canary no longer orphans pods** - The EKS Pod Identity canary could delete its Job in a loop and leave thousands of finished pods behind in one namespace. This is a backport of the fix released in v3.1.0 for clusters still on the 2.7 line.

## Bug Fixes

### Pod Identity canary orphaned pods in a loop

On clusters configured with `--aws-pod-identity-association-cluster`, the
operator runs a `restate-pia-canary` Job before rolling a `RestateCluster` to
prove that the EKS Pod Identity webhook injects credentials. Two behaviours
combined into a loop:

- The Job was deleted with the API server's default propagation, which for
  `batch/v1` Jobs is orphan, so every deleted canary Job left its pod behind.
- The pod check listed pods by job name only and inspected the first one.
  Once a pod without the injected token had been orphaned, every later check
  found that same pod and deleted the new Job again.

When credentials propagate slowly at environment creation, this left between
a few and several thousand finished canary pods in the namespace.

The pod check is now scoped to the current Job and only shortcuts success.
Missing credentials on an individual pod no longer delete the Job before its
retry can run. Terminally failed Jobs are deleted together with their pods and
retried on the next reconcile. Pod Identity and Workload Identity canary Jobs
now have a five-minute active deadline, so a stalled Job fails and is retried
instead of waiting indefinitely. Successful Jobs are retained.

**Impact on Users:**
- New and existing clusters receive the fix and the deadline on their next
  reconcile.
- Canary pods orphaned before the upgrade are not removed. Delete finished
  `restate-pia-canary` pods without an owner reference separately.

**Migration Guidance:**
No configuration changes are required.

*Related: Issue [#194](https://github.com/restatedev/restate-operator/issues/194), PR [#200](https://github.com/restatedev/restate-operator/pull/200)*

## Upgrading

No CRD changes in this release. Upgrade the operator via Helm:

```bash
helm upgrade restate-operator oci://ghcr.io/restatedev/restate-operator-helm \
  --namespace restate-operator \
  --version 2.7.1
```
