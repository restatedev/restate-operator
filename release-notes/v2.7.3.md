# Restate Operator v2.7.3 Release Notes

## Highlights

- **The 3.x `restate.dev/reconcile` annotation no longer restarts clusters on
  2.7** - 2.7 copied every RestateCluster annotation into the pod template, so
  setting the annotation to prepare an upgrade to 3.x restarted the cluster.
  Backport of [#236](https://github.com/restatedev/restate-operator/pull/236).

## Bug Fixes

### Keep `restate.dev/reconcile` off the objects the operator creates

3.x suspends reconciliation of a resource annotated
`restate.dev/reconcile: disabled`. 2.7 does not act on the annotation, but it
copied it, like every annotation, onto the objects it creates, including the
RestateCluster pod template. Annotating a cluster under 2.7 therefore rolled its
pods. 2.7.3 leaves the annotation out of the RestateCluster,
RestateCloudEnvironment and RestateDeployment objects it creates.

**Impact on Users:**
- A cluster can be annotated under 2.7.3 without restarting. After an upgrade to
  3.x it stays untouched until the annotation is removed, which then costs one
  restart.
- Resources without the annotation: no change.
- Clusters annotated while an earlier 2.7 ran carry the annotation in their pod
  template; 2.7.3 removes it on their next reconcile, which rolls them once.

## Release Workflow

The release workflow now declares the `GITHUB_TOKEN` permissions each job needs,
because the repository's default token became read-only. Backport of
[#233](https://github.com/restatedev/restate-operator/pull/233).
