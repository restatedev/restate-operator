# Restate Operator v3.2.0 Release Notes

See the [v3.1.1 release notes](https://github.com/restatedev/restate-operator/blob/main/release-notes/v3.1.1.md) for changes prior to this release.

## Highlights

- **Configurable tunnel proxy URL for Restate Cloud.** `RestateCloudEnvironment` gets an optional `spec.proxyBaseUrl` for BYOC regions that serve the tunnel proxy under a different name.
- **Pausing no longer restarts pods.** The break-glass annotation `restate.dev/reconcile` is no longer copied onto the objects the operator creates, so setting or removing it leaves the pod template alone.

## Upgrade Notes

- **The RestateCloudEnvironment CRD has a new field.** With the default `installCrds: true` the chart applies it. With `installCrds: false`, apply `crd/restatecloudenvironments.yaml` from this release before rolling the image, or the API server prunes `spec.proxyBaseUrl`.

## New Features

### Configurable tunnel proxy URL for Restate Cloud

#### What Changed
`RestateCloudEnvironment` has a new optional field, `spec.proxyBaseUrl`. When it is set, deployments registered against that environment use its host and port instead of `tunnel.<region>.restate.cloud:9080`. The port defaults to 9080, as it does for the `restate` CLI. This applies to both `tunnelMode: external` and `tunnelMode: in-process`.

#### Why This Matters
Some BYOC regions serve the tunnel proxy under a different name, such as `proxy.<region>.restate.cloud`. On those regions the default URL times out, and registration fails with `META0003`.

#### Impact on Users
- Nothing changes when `proxyBaseUrl` is not set.
- With `tunnelMode: in-process`, setting or changing `proxyBaseUrl` creates a new revision, because the registered URL changes with it.
- With `tunnelMode: external`, a deployment that is already registered keeps its URL. The new URL is used for the next registration, for example on the next rollout.

#### Migration Guidance
Copy the `proxyBaseUrl` that describing your environment returns, for example with the Restate Cloud API:

```yaml
spec:
  region: abc123xyz.byoc.us
  proxyBaseUrl: https://proxy.abc123xyz.byoc.us.restate.cloud:9080
```

## Bug Fixes

### `restate.dev/reconcile` is no longer copied to owned objects

#### What Changed
The operator copies a resource's annotations onto the objects it creates, including the RestateCluster's pod template. The break-glass annotation `restate.dev/reconcile` is no longer copied.

#### Why This Matters
Setting or removing the annotation changed the pod template, which rolled the pods. Pausing a cluster under an operator that does not know the annotation (2.x) restarted it, and resuming a cluster whose template carried the annotation restarted it again.

#### Impact on Users
- Resources without the annotation: no change.
- Clusters whose pod template carries the annotation roll once, on their first reconcile with this version: those paused while an older operator reconciled them (after resuming), and those carrying the annotation with any value other than `disabled`, which an older operator copied into the template.
- A ReplicaSet created while its RestateDeployment carried the annotation keeps it on its own metadata. It has no effect there.

#### Migration Guidance
None.

Related: #236 (2.7.3: #237).
